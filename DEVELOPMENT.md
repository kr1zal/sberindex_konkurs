# Контекст проекта

Этот файл — только про то, как устроен проект и чего делать нельзя.

## Что это

Работа на онлайн-конкурс СберИндекса по анализу данных, экономике и машинному обучению.
Направление — **«Прогнозирование»**. Дедлайн подачи — **9 октября 2026**.

Задача: прогнозировать потребление в муниципальных образованиях и заранее выявлять точки
структурных изменений, превзойдя базовую модель по MAE.

## Жёсткие ограничения из Положения о конкурсе

- **п. 9.1.2** — проект должен быть создан во время конкурса и не являться развитием
  существующего. Первый коммит не раньше 14 сентября 2026. Ничего не переносить из старых репозиториев.
- **п. 10.3** — запрещены проприетарные технологии, требующие возмездного приобретения прав.
  Только open source. TimeGPT и платные API исключены.
- **п. 9.2.1** — нельзя использовать материалы способом, нарушающим права третьих лиц.
  Обход антибот-защит при сборе данных исключён; берём только то, что разрешено robots.txt.
- **MAE обязательна** по условиям конкурса.

## Устройство репозитория

```
configs/baseline.yaml   протокол оценки: данные, разбиение, выборка, модели, параллелизм
src/data.py             загрузка панели, восстановление сущностей МО, обработка пропусков
src/regions.py          привязка к регионам и ОКТМО по справочнику СберИндекса
src/split.py            скользящий origin с расширяющимся окном
src/metrics.py          MAE, R², sMAPE, MASE
src/models/             модели прогноза за единым интерфейсом fit/predict
src/changepoints.py     детекторы точек структурных изменений
src/run.py              прогон и сводка
data/raw/               панель СберИндекса (parquet)
data/reference/         справочник муниципалитетов
results/                выход прогонов (в git не попадает)
```

## Правила работы

- **Протокол оценки меняется только в `configs/baseline.yaml`.** Никаких параметров разбиения
  или горизонта в коде моделей — иначе сравнение перестаёт быть сравнением.
- **Новая модель подключается** реализацией `fit(y) -> self` и `predict(horizon) -> np.ndarray`
  плюс регистрацией в `src/run.py::REGISTRY`. Больше ничего трогать не нужно.
- **Тяжёлые прогоны — в фон**, вывод не пропускать через `grep` (он буферизует и лог остаётся пустым).
  Python запускать с `-u`.
- **Числа в отчёт попадают только из прогонов**, не из памяти и не из головы.
- Комментарии в коде объясняют **почему**, а не что. «Что» видно из кода.

## Чего не делать

- Не подгонять базовую модель под себя. Если конфигурация эталона меняется, обе версии
  считаются как отдельные модели и показываются обе.
- Не выбрасывать данные молча. Любое исключение ряда попадает в отчёт прогона.
- Не приписывать регион по названию, если название омонимично. Лучше «не определено», чем неверно.
